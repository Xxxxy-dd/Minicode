# MiniCode Agent 核心概念说明

## 1. Skill 分层路由系统

### 一句话定义
先判断当前任务该用哪类能力，再决定注入哪一个具体 Skill。

### 结构
- 原子 Tool 层：`read_file`、`edit_file`、`run_tests` 等最底层动作。
- 高层 Skill 层：`debugging`、`test-writing`、`code-review` 等任务能力包。
- Skill 元信息层：每个 Skill 的描述、标签、示例、适用场景。

### 路由流程
```text
用户任务
-> 任务意图识别
-> 粗筛相关 Skill
-> 精排候选 Skill
-> 注入最合适的 Skill
```

### 解决的问题
- Skill 太多时找不到合适的。
- Skill 之间容易重复。
- 每次都塞一堆 prompt，token 浪费。
- 不同任务需要动态切换能力。

### 项目里的对应实现
- 目前已有 `Skill` 概念和 `RuleBasedPlanner` 雏形。
- 现在先用规则做路由，后面接模型后可以做更精细的检索和 rerank。

### 面试表达
> Skill 分层路由不是 prompt 拼接，而是先识别任务意图，再选择最合适的能力包，减少冗余上下文和错误策略。

## 2. 自进化记忆沉淀

### 一句话定义
把执行过程中有复用价值的经验自动提炼出来，存成以后还能检索和复用的记忆。

### 记忆类型
- Project memory：项目事实，例如测试命令、目录结构。
- User memory：用户偏好，例如中文回复、常用工具。
- Procedure memory：解决某类问题的流程。
- Failure memory：失败案例和修复策略。

### 闭环流程
```text
执行任务
-> 反思
-> 提炼经验
-> 分类存储
-> 下次检索并复用
```

### 解决的问题
- 同类问题每次都重新想。
- 上下文越聊越长。
- 经验不沉淀，Agent 不会“越用越聪明”。

### 项目里的对应实现
- 目前已经有 `RuntimeContext`、`TraceStore`、`AgentLoop` 这些基础设施。
- 后续会在任务结束后做 reflection，把稳定经验写入 memory。

### 面试表达
> 自进化记忆不是聊天记录，而是把稳定、可复用的经验从执行过程中自动抽取出来，形成能在后续任务里复用的资产。

## 3. 分层上下文压缩

### 一句话定义
把长上下文按重要程度分层保留，越关键的越完整，越不关键的越压缩。

### 三层结构
- Hot context：当前任务最相关的信息，尽量保留原文。
- Warm context：历史步骤、摘要、关键决策。
- Cold context：完整 trace、旧输出、可检索归档。

### 压缩结果
不是简单摘要，而是结构化任务状态：

```text
goal
constraints
known_facts
decisions
failed_attempts
files_relevant
files_modified
next_actions
```

### 解决的问题
- 长任务 token 爆炸。
- 模型忘记关键约束。
- 工具输出太长，后面看不到重点。
- 一直读无效内容。

### 项目里的对应实现
- 现在已经在做 trace 清理、payload 压缩、结构化状态 `TaskState`。
- 这些都是后面正式做上下文压缩的前置基础。

### 面试表达
> 分层上下文压缩不是简单总结，而是把长任务里最关键的目标、约束、决策和失败尝试保留下来，其他内容按层压缩或归档。

---

## 4. 一句话总括

> Skill 分层路由负责“先选对能力”，自进化记忆负责“把经验留下来”，分层上下文压缩负责“让长任务不爆 token 也不丢关键约束”。
